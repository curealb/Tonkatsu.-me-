# Architecture / v0.1

## 唯一渲染核心

```text
浏览器本地音频.currentTime ── /api/frame?t=… ──┐
                                               ├─ Film.render() ── Canvas
终端 mpv JSON IPC time-pos ────────────────────┘                    ├─ ANSI → 真实终端
timeline.json + assets/ascii ──────────────────────────────────────└─ 样式文本行 → 浏览器
```

浏览器预览只传输时间、尺寸、音量强度、偏移和开关；本地选择的音频不上传。使用 `media/song.mp3` 自动加载时，音频经同一个仅监听回环地址的服务发送到本机浏览器。没有在线服务或外部脚本。

## 时间轴与场景

`timeline.json` 定义连续、无空隙、无重叠的区间。`Timeline` 在启动时检查完整性；`bisect_right` 实现随机定位。`scene` 对应 `SCENES` 中注册的函数，`params` 区分同类视觉变体。改变分镜顺序或开始时间不需改主循环。

场景函数读取 `Stage`，画入本帧 Canvas。时间、哈希颗粒和曲线都是确定性的；先播放过哪一段不会影响当前帧。暂停与跳转不需要回放旧状态。没有逐帧视频素材和游戏原图。

食物是程序化几何：带面包糠纹理的椭圆体、切面线、盘子、可控缺口。用户画好的两个食物槽标为 `ready` 后，`Stage.food()` 用转换后的图片字符层替换主食物；部分数学化、飞散或缩略食物仍由程序绘制，便于保持动态。

## 音频与时钟

浏览器直接使用 `HTMLAudioElement.currentTime`。请求回来可能晚于发起时刻，故存在本地请求和绘制延迟；没有声称硬实时或零延迟。跳转时以版本号丢弃旧帧响应。Web Audio 音量测量仅驱动局部参数，不影响时钟。

终端有明确分开的两种时钟：`DemoClock` 用单调时钟作无声演示；`MpvClock` 从实际音频播放器观察 `time-pos`、`pause`、`duration` 与 EOF。音频模式不把系统计时当作歌曲进度。mpv 使用随机私有临时目录内的 Unix-domain socket；启动失败或正常关闭都会清理。

本项目不含 Swift 后端。选择 mpv 是为了让 macOS/Linux 终端共享一个明确的音频控制协议；不想安装 mpv 时使用浏览器入口。Windows 交互终端尚未实现，浏览器与快照可用。

## 图片替换

原始 PNG → 可选 Pillow 转换 → `assets/ascii/<slot>.txt` → `Artwork` → 场景。

原图和音频默认不提交。文本资产只接受可打印 ASCII，避免控制序列、超大尺寸或未知终端宽度行为。中文独白由 Canvas 的宽字符逻辑另行绘制，不经过 ASCII 图片转换。

## 界面与安全边界

预览只允许明确的静态路由、元数据、帧接口和一个显式配置的音频文件。没有任意文件路径读取、目录列表、上传、执行命令或写文件端点。Host 验证减轻 DNS rebinding 风险。接口数字限制为有限且有界的值，限制画布分配大小。

输出行只携带样式名和文本；浏览器通过 `textContent` 构建字符画面，不把字幕或资产解释成 HTML。样式名有白名单。服务不是经过完整安全审计的公网产品，不应暴露至公网。

动态效果没有全屏闪烁，并提供减弱动态模式。减弱模式减少干扰和部分空间运动，但不会暂停所有角色、油锅和计时动画；仍可随时暂停。
